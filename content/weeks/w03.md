## D1 · Decision trees

A tree recursively splits the feature space with axis-aligned thresholds, choosing at each node the split that
most reduces **impurity**:

```math
\text{Gini}(S)=1-\sum_k p_k^2,\qquad H(S)=-\sum_k p_k\log_2 p_k,\qquad \text{Gain}=I(S)-\frac{|S_L|}{|S|}I(S_L)-\frac{|S_R|}{|S|}I(S_R)
```

For regression the impurity is the variance (MSE); each leaf predicts the mean of its samples.

**Finding the best split** for one numeric feature: sort the values once, sweep the threshold left-to-right while
updating class counts incrementally — $O(n\log n)$ per feature per node instead of $O(n^2)$. Histogram-based
libraries bucket features into ~256 bins first, making it $O(n)$.

**Properties.** Trees need no feature scaling, handle mixed types and interactions, are interpretable when
shallow, and are **high-variance**: a small data change can change the top split and the whole tree. They
can't extrapolate beyond the range of the training targets (a regression tree predicts a constant outside the
data).

**Controlling overfitting:** max depth, min samples per leaf, min impurity decrease, cost-complexity pruning
(grow fully, then prune subtrees by $R_\alpha(T)=R(T)+\alpha|T|$).

Gini and entropy almost always choose the same splits; Gini is cheaper (no log). Information gain is biased
towards features with many distinct values (an ID column splits perfectly) — C4.5 uses the gain ratio to
correct this.

> **Interview angle.** "Why do trees not need feature scaling?" — splits depend only on the ordering of values
> within a feature, which any monotonic transform preserves.

## D2 · Ensembles: bagging, random forests and gradient boosting

**Bagging** trains B models on bootstrap samples and averages them. For B models each with variance
$\sigma^2$ and pairwise correlation $\rho$, the ensemble variance is $\rho\sigma^2 + \frac{1-\rho}{B}\sigma^2$ —
averaging kills the second term but not the first, so you want **decorrelated** models.

**Random forests** decorrelate trees further by sampling a random subset of features at every split
($\sqrt d$ for classification is typical). Deep, unpruned trees (low bias, high variance) + averaging = low
variance. **Out-of-bag** samples (~37% left out of each bootstrap, since $(1-1/n)^n\to e^{-1}$) give a free
validation estimate.

**Boosting** fits models sequentially, each correcting the previous ensemble; it mainly reduces **bias**, using
shallow trees (depth 3–8).

**Gradient boosting** is gradient descent in function space. With loss $L(y,F)$:

1. Start with $F_0$ = constant (e.g. mean).
2. For $m = 1..M$: compute pseudo-residuals $r_i = -\partial L(y_i,F)/\partial F\,|_{F_{m-1}(x_i)}$, fit a tree
   $h_m$ to them, set $F_m = F_{m-1} + \nu\, h_m$ with **shrinkage** $\nu\approx 0.05$–$0.1$.

For squared loss the pseudo-residuals are literally the residuals $y-F$. For log-loss they're $y-p$.
Smaller $\nu$ with more trees generalises better; row and column subsampling (stochastic GB) add variance
reduction. Overfitting is controlled with early stopping on validation loss.

> **Interview angle.** RF vs GBDT in one line: RF averages many deep independent trees (variance reduction,
> robust, hard to overfit with more trees); GBDT adds many shallow dependent trees (bias reduction, usually more
> accurate, needs tuning and early stopping).

## D3 · XGBoost, LightGBM and CatBoost internals

**XGBoost's objective** adds a complexity penalty to each tree: $\Omega(f)=\gamma T + \tfrac12\lambda\sum_j
w_j^2$ ($T$ leaves, leaf weights $w_j$). It uses a **second-order** Taylor expansion of the loss with
gradients $g_i$ and Hessians $h_i$. For a leaf with sample set $I_j$, the optimal weight and the gain of a split
are:

```math
w_j^*=-\frac{G_j}{H_j+\lambda},\qquad \text{Gain}=\tfrac12\left[\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{(G_L+G_R)^2}{H_L+H_R+\lambda}\right]-\gamma
```

where $G=\sum g_i$, $H=\sum h_i$. A split is kept only if Gain > 0, so $\gamma$ acts as pre-pruning. The
Hessian lets the same algorithm handle any twice-differentiable loss (log-loss: $g=p-y$, $h=p(1-p)$).

**Engineering tricks.** Histogram binning of features; **sparsity-aware** splits that learn a default
direction for missing values; column blocks for parallel split finding; cache-aware access.

**LightGBM:** leaf-wise (best-first) growth instead of level-wise — lower loss for the same number of leaves,
but needs `num_leaves`/`max_depth` limits; **GOSS** keeps all large-gradient samples and subsamples
small-gradient ones; **EFB** bundles mutually exclusive sparse features.

**CatBoost:** **ordered target statistics** for categorical features (encode each row using only rows
"before" it in a random permutation, avoiding target leakage) and ordered boosting; symmetric (oblivious)
trees that are very fast at inference.

**Feature importance pitfalls.** Split-count and gain importances are biased towards high-cardinality
features; permutation importance is better but suffers with correlated features; **SHAP** (TreeSHAP is exact
and fast for trees) gives consistent per-prediction attributions.

> **Interview angle.** On tabular data, well-tuned GBDTs still match or beat deep nets in most benchmarks.
> Saying so — and when deep learning wins (raw signals, images, audio, text, very large data, multimodal) —
> signals maturity.

## D4 · SVMs, kernels and k-nearest neighbours

**Linear SVM:** find the hyperplane with maximum margin $2/\|w\|$. Soft-margin primal:

```math
\min_{w,b}\ \tfrac12\|w\|^2 + C\sum_i \max(0,\,1-y_i(w^\top x_i+b))
```

That's L2-regularised **hinge loss**. Only points on or inside the margin (**support vectors**) affect the
solution. Large $C$ = less regularisation.

**Dual and the kernel trick.** The dual depends on data only through dot products $x_i^\top x_j$; replacing
them with a kernel $k(x_i,x_j)=\phi(x_i)^\top\phi(x_j)$ fits a linear separator in a (possibly
infinite-dimensional) feature space without computing $\phi$. RBF kernel $e^{-\gamma\|x-x'\|^2}$: large
$\gamma$ = very local, wiggly boundary. Kernel SVMs cost $O(n^2)$–$O(n^3)$ in training and keep the support
vectors for inference, so they don't scale to millions of samples.

**SVM vs logistic regression:** similar linear boundaries; hinge loss ignores well-classified points (sparse
in support vectors), log-loss gives probabilities. SVM scores aren't probabilities (use Platt scaling).

**k-NN** stores the training set and predicts by majority vote / average of the k nearest points. No training,
expensive inference ($O(nd)$ per query without an index; use KD-trees for low $d$, approximate nearest
neighbours — HNSW, IVF-PQ — for high $d$). Small k = high variance. Needs scaled features.

**Curse of dimensionality.** In high dimension, distances concentrate: the nearest and farthest neighbours are
almost equally far, and the volume needed to capture a fixed fraction of the data covers most of each axis.
Distance-based methods then degrade unless the data lives on a low-dimensional manifold — which is why learned
embeddings + ANN search works.

> **Interview angle.** Vectorised pairwise distances: $\|a-b\|^2 = \|a\|^2 + \|b\|^2 - 2a^\top b$ — one matrix
> multiply instead of a Python double loop. You'll write this in code (it's also how attention scores and
> k-means assignments are computed).

## D5 · Generative vs discriminative, Naive Bayes, and practical tabular ML

**Discriminative** models learn $p(y\mid x)$ directly (logistic regression, SVM, most deep nets).
**Generative** models learn $p(x\mid y)p(y)$ and apply Bayes' rule (Naive Bayes, LDA/QDA, GMM classifiers,
HMMs). Generative models handle missing features and small data better and can generate samples;
discriminative models usually win with enough data.

**Naive Bayes** assumes features are conditionally independent given the class:
$p(y\mid x)\propto p(y)\prod_j p(x_j\mid y)$. Compute in log space; use Laplace (add-one) smoothing so an
unseen word doesn't zero the product. Probabilities are poorly calibrated (the independence assumption
double-counts correlated evidence) but the ranking is often good — a strong text baseline.

**LDA / QDA:** Gaussian class-conditionals with shared (LDA → linear boundary) or per-class (QDA → quadratic)
covariance.

**Practical tabular checklist** (frequent interview follow-ups):

* *Categoricals:* one-hot for low cardinality; target/mean encoding for high cardinality — **fit within CV folds**
  or it leaks; hashing for huge vocabularies; learned embeddings in neural nets.
* *Missing values:* is "missing" informative? Add an indicator; GBDTs handle NaN natively.
* *Skewed targets:* log-transform or use a matching loss (Poisson, Tweedie).
* *Model choice:* small data / interpretability → linear or shallow tree; tabular → GBDT; raw signals → DL.

> **Interview angle.** "Why is it called naive, and why does it still work?" — the independence assumption is
> almost always false, but classification only needs the arg-max to be right, not the probabilities.

## Questions

??* d1 [trees] | How does a decision tree choose a split, and how do you make split-finding fast?
For each candidate feature and threshold it computes the weighted impurity of the children (Gini or entropy for
classification, variance for regression) and picks the largest decrease. Fast version: sort each feature once
and sweep thresholds while updating left/right counts incrementally, O(n log n) per feature; histogram methods
bin features into ~256 buckets and accumulate per-bin statistics in O(n), and can compute one child's histogram
by subtracting the sibling's from the parent's.

?? d1 [trees] | Why can't a regression tree (or a GBDT) extrapolate?
Each leaf predicts a constant: the mean (or optimal value) of the training targets in that region. Outside the
range of the training features, the input falls into an edge leaf and gets that constant, so predictions are
bounded by the training targets. For trending data, detrend first, or use a linear model / linear trees.

??* d2 [ensembles] | Random forest vs gradient boosting: how do they differ and when would you pick each?
RF trains deep trees independently on bootstrap samples with random feature subsets and averages them: it
reduces variance, is robust with defaults, parallelises, and doesn't overfit as trees are added. GBDT trains
shallow trees sequentially on the negative gradient of the loss, with shrinkage: it reduces bias, is usually
more accurate, but needs tuning (learning rate, depth, number of trees) and early stopping. Pick RF for a quick,
robust baseline; GBDT when you want the best tabular accuracy.

?? d2 [ensembles] | Why does a random forest sample features at each split, not just bootstrap rows?
Bagging's variance is $\rho\sigma^2+(1-\rho)\sigma^2/B$; averaging can't remove the correlated part. With only
row bootstrapping, a few strong features dominate the top splits of every tree, so the trees stay highly
correlated. Random feature subsets force different trees to use different features, lowering ρ and therefore
the ensemble variance.

??* d2 [boosting] | Explain gradient boosting as gradient descent in function space.
We want the function $F$ that minimises $\sum_i L(y_i,F(x_i))$. At step m, the steepest-descent direction at the
training points is the negative gradient $r_i=-\partial L/\partial F(x_i)$. We can't move $F$ freely, so we fit a
tree $h_m$ to approximate $r$ (that's the projection onto the function class) and take a small step
$F_m=F_{m-1}+\nu h_m$. For squared loss $r_i$ is the residual; for log-loss it's $y_i-p_i$.

??* d3 [boosting] | Derive XGBoost's optimal leaf weight and split gain.
Second-order Taylor: $L\approx\sum_i[g_i w_{q(i)}+\frac12 h_i w_{q(i)}^2]+\gamma T+\frac12\lambda\sum_j w_j^2$.
Group by leaf: $\sum_j[G_jw_j+\frac12(H_j+\lambda)w_j^2]+\gamma T$. Minimising each quadratic gives
$w_j^*=-G_j/(H_j+\lambda)$ with value $-\frac12 G_j^2/(H_j+\lambda)$. The gain of splitting a leaf is the score of the
two children minus the parent: $\frac12[G_L^2/(H_L+\lambda)+G_R^2/(H_R+\lambda)-(G_L+G_R)^2/(H_L+H_R+\lambda)]-\gamma$.

?? d3 [boosting] | What do LightGBM's leaf-wise growth, GOSS and EFB do?
Leaf-wise growth always splits the leaf with the largest gain (instead of a full level at a time), reaching lower
loss with fewer leaves, at the risk of deep, overfitted branches (limit num_leaves/max_depth). GOSS (gradient-based
one-side sampling) keeps all high-gradient samples and a random subset of low-gradient ones, up-weighting the
latter, to speed up split finding. EFB (exclusive feature bundling) merges sparse features that are rarely non-zero
together into one feature, shrinking the feature count.

??* d4 [svm] | What is the kernel trick, and what are the limitations of kernel SVMs?
The SVM dual objective and prediction depend on the data only through dot products, so you can replace
$x_i^\top x_j$ with a kernel $k(x_i,x_j)$ that equals a dot product in some feature space, fitting a non-linear
boundary without ever computing that space. Limitations: the n×n kernel matrix makes training O(n²) memory and
O(n²–n³) time; inference cost grows with the number of support vectors; and you must choose and tune the kernel
(C, γ). Random Fourier features approximate RBF kernels to scale.

?? d4 [knn, embeddings] | What is the curse of dimensionality, and how does it affect k-NN?
As dimension grows, volume grows exponentially, data becomes sparse, and pairwise distances concentrate: the ratio
of nearest to farthest neighbour distance tends to 1, so "nearest" carries little information. k-NN and other
distance methods then need exponentially more data. In practice real data lies near a lower-dimensional manifold;
learning an embedding (PCA, metric learning, a neural encoder) and searching there with approximate nearest
neighbours (HNSW, IVF-PQ) works well.

?? d5 [probabilistic] | Generative vs discriminative classifiers — trade-offs?
Discriminative models fit p(y|x) directly and usually have lower asymptotic error with enough data. Generative
models fit p(x|y)p(y): they need more assumptions, but converge faster with little data (Ng & Jordan), handle
missing features by marginalising, can detect out-of-distribution inputs via p(x), and can generate samples. Naive
Bayes vs logistic regression is the classic pair.

??* d5 [tabular, leakage] | How do you encode a categorical feature with 50,000 levels?
Options: target (mean) encoding with smoothing toward the global mean, computed out-of-fold to avoid leakage (or
CatBoost's ordered target statistics); frequency/count encoding; the hashing trick into a fixed number of buckets;
or a learned embedding table in a neural network. One-hot is too wide and sparse for most models, though linear
models with sparse solvers can cope. Group rare levels into "other".
