## D1 · Uniform affine quantisation

Map a real value $x$ to a $b$-bit integer with a **scale** $s$ and **zero-point** $z$:

```math
q=\mathrm{clamp}\Big(\mathrm{round}\big(\tfrac{x}{s}\big)+z,\ q_{min},\ q_{max}\Big),\qquad \hat x = s\,(q-z)
```

* **Asymmetric** (affine): from a range $[\alpha,\beta]$, $s=\frac{\beta-\alpha}{q_{max}-q_{min}}$, $z=\mathrm{round}(q_{min}-\alpha/s)$.
  Good for one-sided activations (post-ReLU). The real value 0 must be exactly representable (padding, ReLU) — that's why $z$ is an
  integer.
* **Symmetric:** $z=0$, $s=\max|x|/(2^{b-1}-1)$ (use $[-127,127]$ to keep it symmetric). Standard for **weights**; cheaper integer
  math (no zero-point cross terms).
* **Unsigned vs signed** int8 for activations — runtime conventions differ (TFLite uses int8 asymmetric activations, symmetric
  per-channel weights).

**Two error sources:** **rounding** error (uniform, variance $s^2/12$ for values inside the range) and **clipping** error (values outside
$[\alpha,\beta]$). A wider range lowers clipping but raises rounding error for everything else — the central trade-off of calibration.

**Quick numbers:** int8 → 256 levels; int4 → 16. Going from 8 to 4 bits multiplies rounding noise power by 256.

**Per-layer error metrics:** MSE, **SQNR** $=10\log_{10}\frac{\|x\|^2}{\|x-\hat x\|^2}$, cosine similarity of outputs vs float.

> **Interview angle.** "Why must zero be exactly representable?" — zero-padding in convs and ReLU outputs are extremely common; if 0
> maps to a non-integer level, every padded value carries a bias error that accumulates.

## D2 · Granularity and calibration

**Granularity** (one scale per …):

* **Per-tensor:** simplest, worst when channels have different ranges.
* **Per-channel** (per output channel of weights): standard for conv/linear weights; essential for **depthwise** convs, whose
  per-channel ranges vary hugely. Costs nothing at inference (the scale folds into the requantisation per channel).
* **Per-group** (e.g. 32/64/128 consecutive input elements share a scale): the LLM standard for 4-bit weights; also the idea behind MX
  formats.
* **Per-token** activations (dynamic): one scale per row computed at runtime.

**Activation calibration** (static quantisation: fix activation ranges from a calibration set of ~100–1000 representative samples):

* **Min–max:** sensitive to outliers.
* **Percentile** (e.g. 99.99%): clips rare outliers.
* **MSE-optimal:** search the clipping range that minimises quantisation MSE.
* **KL / entropy** (TensorRT): choose the range that minimises KL divergence between the float and quantised histograms.

**Static vs dynamic quantisation:** static fixes activation scales offline (fastest, needed for integer-only NPUs); dynamic computes
activation scales per batch/token at runtime (more accurate for LSTMs/transformers with varying ranges; common on CPUs).

**Sensitivity and mixed precision:** first and last layers, depthwise convs, attention softmax inputs, and residual adds are often most
sensitive. Measure per-layer sensitivity (quantise one layer at a time and check the metric drop), keep sensitive layers at int16/FP16,
or use a mixed-precision search (HAWQ uses Hessian traces).

**Audio-specific:** log-mel inputs have a fixed known range (calibrate once or quantise front-end output directly); RNN states and
gates need care (int16 states, LUT sigmoid/tanh); SI-SDR/PESQ, not just MSE, to judge degradation.

> **Interview angle.** "Calibration data mismatch" is a classic failure: calibrating on clean speech then deploying in a noisy car
> clips activations. Calibrate on deployment-like data.

## D3 · Integer-only inference and requantisation

For $y=Wx$ with $\hat W=s_W(q_W - z_W)$, $\hat x=s_x(q_x-z_x)$ and output $\hat y = s_y(q_y-z_y)$:

```math
q_y = z_y + \frac{s_Ws_x}{s_y}\sum_k (q_{W,k}-z_W)(q_{x,k}-z_x)
```

* Compute the sum in **int32** (int8 × int8 products, many terms).
* Expand the zero-point terms: $\sum q_Wq_x - z_x\sum q_W - z_W\sum q_x + Kz_Wz_x$ — the $\sum q_W$ terms are precomputed offline; with
  symmetric weights ($z_W=0$) only one correction remains.
* **Bias** is stored in int32 with scale $s_Ws_x$ and zero-point 0, added to the accumulator.
* **Requantisation:** the real multiplier $M=s_Ws_x/s_y$ (typically in $(0,1)$) is represented as $M=M_0\cdot2^{-n}$ with $M_0\in[0.5,1)$
  stored as a Q31 integer; then `q = rounding_doubling_high_mul(acc, M0) >> n` (with correct rounding), add $z_y$, **clamp** to int8.
  Per-channel weights → per-channel $M$.
* **Fused activation:** ReLU/ReLU6 become a clamp of the output range — free.
* **BatchNorm** is folded into weights/bias before quantisation (week 6).

This is the scheme from Jacob et al. (2018) used by TFLite, CMSIS-NN and most NPUs. Element-wise adds of two tensors with different
scales also need rescaling (both inputs requantised to a common scale).

> **Interview angle.** Implement an int8 linear layer with int32 accumulation and multiplier/shift requantisation, and show it matches
> the float reference to within 1 LSB — this week's exercise, and a great embedded-ML interview story.

## D4 · Advanced post-training quantisation

When plain round-to-nearest (RTN) PTQ loses too much accuracy:

* **Cross-layer equalisation (CLE, Data-Free Quantisation):** for consecutive layers with a positively homogeneous activation (ReLU),
  scale channel $i$ of layer 1 by $1/s_i$ and the corresponding input channel of layer 2 by $s_i$ — the function is unchanged, but per-
  channel ranges become balanced, so per-tensor quantisation works much better (critical for MobileNets).
* **Bias correction:** quantisation shifts the expected output $\mathbb E[\hat Wx]-\mathbb E[Wx]=\Delta W\,\mathbb E[x]$; subtract it from
  the bias (using calibration statistics or BN statistics).
* **AdaRound:** rounding to nearest isn't optimal for the layer's *output*; learn per-weight up/down rounding decisions by minimising
  the layer-output reconstruction error on calibration data. Big gains at 4 bits.
* **BRECQ / block reconstruction:** optimise rounding and scales per block (residual block / transformer block) instead of per layer.
* **GPTQ** (week 23) is the LLM-scale cousin: second-order error compensation column by column.
* **Outlier channel splitting**, **SmoothQuant** (week 23) for activation outliers.

**Typical outcomes:** CNNs at W8A8 with per-channel weights lose <1% top-1; MobileNets need CLE or QAT; W4A8 CNNs need AdaRound or QAT;
transformers at W8A8 need outlier handling.

> **Interview angle.** "Your int8 MobileNetV2 lost 10% accuracy with per-tensor quantisation" → per-channel weights (depthwise!),
> CLE, bias correction, better activation calibration; QAT if still not enough.

## D5 · Quantisation-aware training (QAT)

**Fake quantisation:** insert quantise→dequantise ops in the forward pass so the network trains with quantisation noise but in float.
Rounding has zero gradient almost everywhere → use the **straight-through estimator (STE)**: in backward, pass gradients through as
identity inside the clipping range and zero outside (clipped STE).

**Learnable quantisation parameters:**

* **PACT:** learn the clipping value of activations.
* **LSQ (Learned Step Size Quantisation):** learn the scale $s$ by gradient descent with the STE, scaling its gradient by
  $1/\sqrt{N\cdot q_{max}}$ for stable training. Strong 2–4-bit results; LSQ+ adds learnable offsets.

**Practical recipe:**

1. Start from a well-trained float model (or PTQ-initialised scales).
2. Fold BN into conv weights during QAT (or simulate folding) and **freeze BN statistics** after a few epochs.
3. Fine-tune for ~5–10% of original training with a small LR; observers stop updating ranges after a while.
4. Export to the integer runtime and **re-verify** accuracy on device (bit-exactness of requantisation/rounding matters).

**PyTorch tooling:** PT2E quantisation — `torch.export` the model, `prepare_pt2e(model, quantizer)` with a backend-specific quantizer
(XNNPACK, Arm Ethos-U, Qualcomm), calibrate (PTQ) or train (`prepare_qat_pt2e`), `convert_pt2e`, then lower to ExecuTorch. torchao
provides LLM-oriented QAT (e.g. int4 weight / int8 dynamic activation).

**When QAT is worth it:** ≤ 4-bit weights, sensitive models (small MobileNets, audio RNNs, low-SNR enhancement), integer-only targets
where you can't keep layers in float. Frontier labs now do QAT at the end of LLM training (Kimi K2 Thinking INT4, DeepSeek-V4 FP4
experts, Kimi K3 MXFP4).

> **Interview angle.** "How does the gradient flow through a rounding operation in QAT?" — it doesn't, mathematically; the STE
> approximates its derivative as 1 within the clip range, and LSQ adds a gradient for the scale itself.

## Questions

??* d1 [quantization] | Write the affine quantisation formulas and explain symmetric vs asymmetric quantisation.
q = clamp(round(x/s) + z, q_min, q_max) and x̂ = s(q − z). Asymmetric uses a zero-point so an arbitrary range [α, β] maps onto the integer range:
s = (β − α)/(q_max − q_min), z = round(q_min − α/s); it uses levels efficiently for skewed data such as post-ReLU activations. Symmetric fixes z = 0
and s = max|x|/(2^{b−1} − 1); it wastes some range for skewed data but avoids zero-point cross terms in integer matmuls, so it's standard for
weights. Zero must be exactly representable in both.

??* d1 [quantization] | What are the two sources of quantisation error, and how does calibration trade them off?
Rounding error (values inside the range are rounded to the nearest level; variance ≈ s²/12) and clipping error (values outside the range are
saturated). A larger range reduces clipping but increases s and therefore rounding error for all values; a smaller range does the opposite.
Calibration chooses the range to minimise total error for the actual distribution: min–max (no clipping, poor with outliers), percentile, MSE-
optimal search or KL-divergence matching.

??* d2 [quantization] | Why is per-channel weight quantisation important, especially for depthwise convolutions?
Different output channels can have weight ranges differing by orders of magnitude; one per-tensor scale set by the largest channel leaves small
channels with only a few effective levels. Per-channel scales give each channel its full resolution, and cost nothing at inference because the
scale folds into the per-channel requantisation multiplier. Depthwise convs have one filter per channel with very different ranges and few weights
each, so per-tensor quantisation often destroys accuracy (MobileNet's classic int8 problem).

?? d2 [quantization] | Static vs dynamic activation quantisation — when do you use each?
Static: activation ranges are calibrated offline and fixed, so inference is integer-only and fastest — required for most NPUs/DSPs/MCUs, good for
CNNs with stable activation statistics. Dynamic: activation scales are computed at runtime per tensor/token from the actual values, which is more
accurate for models with input-dependent ranges (LSTMs, transformers, LLM linear layers) but adds runtime reductions and usually needs float
support; common on CPUs (e.g. int8 dynamic activation × int4 weights).

??* d3 [quantization, embedded] | How does an int8 linear layer compute its output with integer-only arithmetic?
Accumulate Σ(q_W − z_W)(q_x − z_x) in int32, expanding zero-point terms with precomputed weight sums (z_W = 0 for symmetric weights), and add the
int32 bias quantised with scale s_W·s_x. Rescale to the output scale with M = s_W·s_x/s_y, represented as a Q31 fixed-point multiplier M₀ ∈ [0.5, 1)
and a right shift n: apply a rounding high multiply by M₀, rounding shift by n, add z_y, and clamp to the int8 range (which also implements fused
ReLU/ReLU6). Per-channel weight scales give per-channel (M₀, n).

?? d3 [quantization] | How do you handle a residual addition of two int8 tensors with different scales?
Both inputs must be brought to a common scale before adding: rescale each to the output scale (or a shared intermediate scale) with its own
fixed-point multiplier and shift, in higher precision (int32), add, then requantise and clamp to int8. Mismatched scales on residual adds are a
frequent source of accuracy loss, so some toolchains constrain both branches to share a scale.

??* d4 [quantization] | What is cross-layer equalisation and why does it help MobileNets?
For two consecutive layers with a ReLU (positively homogeneous) between them, scaling output channel i of the first layer by 1/sᵢ and the matching
input channel of the second by sᵢ leaves the network function unchanged. Choosing sᵢ to equalise per-channel weight ranges (sᵢ = √(r₁ᵢ/r₂ᵢ)) makes
per-tensor quantisation much more accurate. MobileNets' depthwise layers have extremely uneven channel ranges, so CLE recovers most of the int8
accuracy loss without data or retraining.

?? d4 [quantization] | What does AdaRound improve over round-to-nearest?
Rounding each weight to its nearest grid point minimises per-weight error, but not the error of the layer's output, because errors in different
weights interact through the inputs. AdaRound learns, per weight, whether to round up or down (a continuous relaxation annealed to binary) to
minimise the reconstruction error of the layer output on calibration data. It gives large gains at 4-bit weights with only a small unlabelled
calibration set.

??* d5 [qat] | How does quantisation-aware training work, and what is LSQ?
QAT inserts fake-quantisation (quantise then dequantise) in the forward pass so the model adapts to quantisation noise during fine-tuning. Because
rounding has zero gradient almost everywhere, backward uses the straight-through estimator: gradient 1 inside the clipping range, 0 outside. LSQ
makes the scale itself a learnable parameter with a gradient derived through the STE (scaled by 1/√(N·q_max) for stability), so the network learns
the best step size per layer/channel. Fold BN and freeze its statistics late in QAT, then export to the integer runtime.

?? d5 [qat] | When is QAT worth the extra effort compared with PTQ?
When PTQ accuracy loss is unacceptable: weights at 4 bits or below, very compact or sensitive models (small MobileNets, low-SNR speech enhancement,
RNNs), integer-only targets where sensitive layers can't stay in float, or extreme formats (ternary/binary, FP4). If PTQ with per-channel scales,
good calibration and CLE/AdaRound already meets the target at W8A8, QAT adds cost (training pipeline, data, time) for little benefit.
