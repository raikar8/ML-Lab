## D1 · Convolution arithmetic and im2col

For input size $W$, kernel $k$, padding $p$, stride $s$, dilation $d$:

```math
W_{out}=\left\lfloor\frac{W+2p-d(k-1)-1}{s}\right\rfloor+1
```

"Same" padding for stride 1 and odd $k$ is $p=(k-1)/2$.

**Parameters** of a 2-D conv: $C_{out}\cdot C_{in}\cdot k_h k_w$ (+ $C_{out}$ biases).
**MACs** (multiply–accumulates): $C_{out}\cdot C_{in}\cdot k_hk_w\cdot H_{out}W_{out}$. FLOPs ≈ 2 × MACs.
Parameters are independent of the input size; compute scales with it.

**Receptive field** of stacked layers grows as $r_l = r_{l-1} + (k_l-1)\prod_{i<l}s_i$ (with dilation, $k$
becomes $d(k-1)+1$). Two 3×3 convs see 5×5 with fewer params than one 5×5 (VGG's insight); dilations grow the
field exponentially (WaveNet, TCNs).

**im2col + GEMM.** Unfold every receptive-field patch into a column: an input of
$(C_{in}, H, W)$ becomes a matrix $(C_{in}k^2,\ H_{out}W_{out})$; the conv is then one matrix multiply with the
weight matrix $(C_{out}, C_{in}k^2)$. That's how many CPU/embedded libraries implement conv (plus Winograd for
3×3, FFT for large kernels), at the cost of $k^2$× memory blow-up for the unfolded input. Implicit-GEMM kernels
avoid materialising it.

**1×1 convolutions** are per-pixel linear layers across channels: cheap channel mixing and dimension changes
(bottlenecks).

**Transposed convolution** (upsampling) is the gradient of a conv w.r.t. its input; it can produce checkerboard
artefacts — resize + conv is often cleaner (relevant for U-Net decoders).

> **Interview angle.** Be fast: "224×224×3 input, 64 filters 7×7, stride 2, pad 3" → output 112×112×64,
> 9,408 params, ≈118M MACs.

## D2 · CNN architecture lineage

* **LeNet → AlexNet (2012):** ReLU, dropout, GPUs, data augmentation.
* **VGG:** stacks of 3×3 convs; simple but heavy (138M params, most in FC layers).
* **Inception/GoogLeNet:** parallel multi-scale branches with 1×1 bottlenecks; global average pooling instead of
  FC layers.
* **ResNet (2015):** residual blocks; bottleneck block 1×1 → 3×3 → 1×1; trained 152 layers. Still the default
  backbone baseline.
* **ResNeXt:** grouped convolutions ("cardinality"). **DenseNet:** concatenate all previous features.
* **SE (squeeze-and-excitation):** global-pool → small MLP → sigmoid channel weights: cheap channel attention,
  used in MobileNetV3/EfficientNet.
* **EfficientNet:** compound scaling of depth, width and resolution together, $d=\alpha^\phi, w=\beta^\phi,
  r=\gamma^\phi$ with $\alpha\beta^2\gamma^2\approx2$.
* **ConvNeXt (2022):** "modernised" ResNet borrowing transformer design — patchify stem, 7×7 depthwise conv,
  inverted bottleneck, LayerNorm, GELU, fewer activations — matching Swin transformers.

**CNN vs ViT.** CNNs bake in locality and translation equivariance (strong inductive bias → data-efficient);
ViTs learn spatial relations from data (better scaling with huge datasets, global context from layer 1). Hybrids
and ConvNeXt show the gap is mostly training recipe. On microcontrollers and DSPs, CNNs still dominate because
their compute is regular and well supported by integer kernels.

> **Interview angle.** "Why global average pooling instead of FC layers?" — far fewer parameters, input-size
> agnostic, less overfitting, and it gives class activation maps for free.

## D3 · Efficient CNNs: depthwise separable, inverted residuals, MobileNets

**Depthwise separable conv** = depthwise $k\times k$ conv (one filter per channel, `groups=C_in`) + pointwise 1×1.
Cost ratio versus a standard conv:

```math
\frac{C_{in}k^2HW + C_{in}C_{out}HW}{C_{in}C_{out}k^2HW}=\frac{1}{C_{out}}+\frac{1}{k^2}
```

≈ 8–9× fewer MACs for 3×3.

**MobileNetV2 inverted residual:** expand with 1×1 (×6), depthwise 3×3, project back with a **linear** 1×1 (no
ReLU in the bottleneck — ReLU in low dimension destroys information), residual between the thin ends.
**MobileNetV3:** NAS-found blocks, SE, **hard-swish** $x\cdot\mathrm{ReLU6}(x+3)/6$ (quantisation-friendly
Swish). **MobileNetV4:** the Universal Inverted Bottleneck (optional depthwise before/after expansion),
mobile multi-query attention, designed to be fast across CPUs, DSPs, GPUs and NPUs. **ShuffleNet:** grouped 1×1 +
channel shuffle. **GhostNet:** generate "ghost" feature maps with cheap linear ops.

**The catch: FLOPs ≠ latency.** A depthwise conv does $k^2$ MACs per loaded activation — very low **arithmetic
intensity** — so it's usually **memory-bandwidth bound**, and many accelerators run it at a few percent of peak.
Element-wise ops and many small layers add launch/memory overhead. That's why hardware-aware NAS measures real
latency on the target, why MobileNetV4 and EfficientNet-EdgeTPU use some full convs ("fused MBConv") in early
layers, and why you should always profile on device. (Week 21 makes this quantitative with the roofline model.)

> **Interview angle.** "Your MobileNet is slower than ResNet-18 on the NPU despite 5× fewer FLOPs" — depthwise
> layers poorly supported / memory-bound, unsupported ops falling back to CPU, layout conversions. Profile per
> layer.

## D4 · Convolutions for audio and streaming

* **Spectrogram + 2-D CNN:** treat time × frequency as an image (KWS, sound event detection). DS-CNN models are
  standard on microcontrollers for keyword spotting (Hello Edge, ~20–40K params).
* **1-D convs on waveforms or features:** **causal** convolutions (pad only on the left) so the output at time
  $t$ uses only inputs $\le t$; **dilated** stacks (WaveNet, TCN) reach long receptive fields cheaply.
* **Conv-TasNet / DCCRN / DCUNet** (your area): encoder–mask–decoder or U-Net structures on waveform or complex
  STFT; complex convolutions $(W_r+iW_i)(x_r+ix_i)$ implemented with real convs.
* **Streaming inference** for causal convs: keep a buffer of the last $(k-1)d$ input frames per layer
  ("state"), concatenate with the new chunk, run the conv without padding, update the buffer. Output then
  matches the offline causal conv exactly. Total **algorithmic latency** = frame size + lookahead (any
  non-causal context), separate from compute latency.
* **Normalisation in streaming:** BatchNorm folds away (fine); LayerNorm over time isn't causal → use per-frame
  norms or cumulative statistics.

> **Interview angle.** For a hearing-aid or in-car NS model, state the latency budget first (hearing aids
> ≈ <10 ms total; telephony ≈ 20–40 ms), then pick frame/hop, lookahead and model size to fit it.

## D5 · Beyond classification, and transfer learning

* **U-Net:** encoder–decoder with skip connections at each scale, preserving detail lost by downsampling — the
  backbone of segmentation, diffusion models and many enhancement networks (DCUNet).
* **Object detection:** two-stage (Faster R-CNN: region proposals + classification) vs one-stage (SSD, YOLO
  family: dense predictions per grid cell); anchors vs anchor-free (FCOS, recent YOLOs); **NMS** (non-maximum
  suppression) removes duplicate boxes by IoU — a classic coding question; DETR uses set prediction and needs no
  NMS.
* **Metrics:** IoU, mAP@[.5:.95].
* **Transfer learning strategies:** linear probe (freeze backbone), fine-tune top layers, full fine-tune with lower
  LR for early layers (discriminative LRs), gradual unfreezing. Freeze BatchNorm statistics when fine-tuning with
  tiny batches.
* **Knowledge transfer to edge models:** fine-tune a big pretrained model, then distil into a small CNN (week 24).

> **Interview angle.** Implement IoU and NMS in NumPy in 15 minutes: sort by score, take the best, drop everything
> with IoU above the threshold, repeat.

## Questions

??* d1 [cnn] | Give the formulas for a conv layer's output size, parameter count and MACs.
Output: ⌊(W + 2p − d(k−1) − 1)/s⌋ + 1 per spatial dimension. Params: C_out·C_in·k_h·k_w (+C_out bias), divided by
groups for grouped convs. MACs: params (without bias) × H_out × W_out, i.e. C_out·(C_in/groups)·k_h·k_w·H_out·W_out.
FLOPs ≈ 2·MACs. Params don't depend on input size; MACs and activation memory do.

?? d1 [cnn] | How does im2col turn a convolution into a matrix multiply, and what's the cost?
Each output position's receptive field (C_in·k·k values) is unrolled into a column, giving a (C_in·k², H_out·W_out)
matrix; multiplying by the (C_out, C_in·k²) weight matrix computes all outputs in one GEMM, which runs at high
efficiency on optimised BLAS. The cost is memory: the unrolled input is up to k² times larger than the original,
which matters on embedded devices; implicit GEMM, Winograd or direct convolution avoid it.

??* d1 [cnn] | How do you compute the receptive field of a stack of convolutions?
Iteratively: r₀ = 1, jump j₀ = 1; for each layer, r ← r + (k_eff − 1)·j and j ← j·s, where k_eff = d(k−1)+1. So
stride multiplies the effect of later kernels, and dilation enlarges each kernel. Example: three 3×3 stride-1
convs → 7×7; with dilations 1,2,4 → 15.

??* d3 [efficient-cnn] | Why is a depthwise separable convolution cheaper, by how much, and why might it not be faster?
It factorises a k×k conv into a per-channel k×k depthwise conv plus a 1×1 pointwise conv, so MACs drop by a factor
of 1/C_out + 1/k² — about 8–9× for 3×3. But the depthwise part has very low arithmetic intensity (k² MACs per
activation loaded, no reuse across channels), so it's memory-bound and accelerators that are built for dense GEMMs
run it far below peak; extra layers also add launch and memory traffic. Measured latency can therefore improve far
less than FLOPs suggest.

?? d3 [efficient-cnn] | Explain MobileNetV2's inverted residual with linear bottleneck.
The block expands a thin input with a 1×1 conv (expansion ~6), applies a 3×3 depthwise conv with ReLU6 in the high
dimension, then projects back to the thin dimension with a 1×1 conv and no activation, adding a residual between
the thin tensors. "Inverted" because the residual connects bottlenecks rather than wide layers; "linear" because a
ReLU in the low-dimensional bottleneck would destroy information. It keeps memory traffic low (thin tensors between
blocks), which suits mobile hardware.

?? d3 [efficient-cnn] | What is hard-swish and why was it introduced?
h-swish(x) = x · ReLU6(x+3)/6, a piecewise-linear approximation of Swish x·σ(x). It keeps most of Swish's accuracy
benefit but avoids the sigmoid, which is expensive and awkward to quantise on mobile/embedded hardware; MobileNetV3
introduced it.

??* d4 [audio, streaming] | How do you run a causal 1-D convolution in streaming mode so that it matches offline output?
Offline, a causal conv left-pads by (k−1)·d. In streaming, keep a per-layer state buffer with the last (k−1)·d input
frames (initialised to zeros, matching the padding). For each new chunk, concatenate state + chunk, run the conv with
no padding, emit the outputs, and store the last (k−1)·d frames as the new state. With strided layers, also track
the phase so chunk boundaries align with the stride. Test by comparing streaming and offline outputs on random input.

?? d4 [audio, latency] | What's the difference between algorithmic latency and compute latency for a real-time speech model?
Algorithmic latency is inherent to the design: the analysis window (or frame) length plus any lookahead the model
uses — it can't be reduced by faster hardware. Compute latency is the time to process one hop on the target
hardware; it must be below the hop size for real-time operation (real-time factor < 1), with margin for the rest of
the audio pipeline. Total delay ≈ algorithmic latency + buffering + compute. E.g. 20 ms window, 10 ms hop, no
lookahead → ≥20 ms algorithmic.

??* d5 [vision] | Implement non-maximum suppression (describe the algorithm and complexity).
Sort boxes by score; repeatedly take the highest-scoring remaining box, keep it, compute its IoU with all remaining
boxes, and discard those with IoU above a threshold (e.g. 0.5). O(n²) worst case, vectorised per step. Per-class NMS
runs this per class (or offsets boxes per class). Soft-NMS decays scores instead of discarding.

?? d5 [transfer-learning] | You fine-tune a pretrained CNN on 2,000 images and accuracy is worse than a linear probe. Why might that be?
Overfitting or catastrophic forgetting from too high an LR on the backbone; BatchNorm statistics corrupted by tiny or
unrepresentative batches (freeze BN or use eval mode for BN); too few epochs for the new head before unfreezing; or
the augmentation/preprocessing doesn't match the pretraining normalisation. Fix: lower or discriminative LRs, warm up
the head first, freeze BN, stronger augmentation, early stopping.
