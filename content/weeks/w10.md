## D1 · Tokenisation and embeddings

A transformer sees a sequence of integer ids; the **tokeniser** decides what they are.

**Subword tokenisation** balances vocabulary size against sequence length:

* **BPE** (GPT family, Llama 3, Qwen, DeepSeek): start from characters/bytes, repeatedly merge the most frequent
  adjacent pair; encoding applies the merges in learned order. **Byte-level BPE** starts from 256 bytes, so any
  string is encodable (no unknown token).
* **WordPiece** (BERT): merges chosen by likelihood gain, `##` continuation prefix.
* **Unigram LM** (SentencePiece, T5): start big, prune tokens that least reduce likelihood; supports sampling
  multiple segmentations (regularisation). SentencePiece treats text as a raw stream with `▁` for spaces.

**Vocabulary size trade-off.** Larger vocab → shorter sequences (cheaper attention, more text per context), better
multilingual coverage, but a bigger embedding table and output softmax. GPT-2: 50K; Llama 3: 128K; DeepSeek-V3:
129K; Qwen3: ~152K; Qwen3.5: ~248K (multilingual + multimodal). On a phone, a 248K × 1024 embedding in BF16 is
~500 MB — that's why small on-device models often tie embeddings and quantise them (8-bit embeddings in ExecuTorch
exports).

**Embedding layer** = a lookup table $E\in\mathbb R^{V\times d}$ (equivalent to one-hot × matrix). The output
layer (LM head) maps $d\to V$. **Weight tying** shares $E$ for both (saves $Vd$ params; common in small models,
less so in large ones). Some models scale embeddings by $\sqrt d$ (original Transformer, Gemma).

**Tokenisation pitfalls worth mentioning:** arithmetic and spelling suffer when digits/characters are merged
(many tokenisers split digits individually); leading-space variants (`"Hello"` vs `" Hello"`) are different tokens;
token-count costs differ across languages; glitch tokens (rare tokens with untrained embeddings).

**Other modalities** become tokens too: image **patches** (ViT: 16×16 patches linearly projected; NaViT-style
packing of native resolutions in Qwen3.5/Kimi's MoonViT), audio frames from a conv encoder, or discrete codec
tokens (RVQ, week 8).

> **Interview angle.** "Why not character-level?" — sequences 4–5× longer, so attention cost and context usage
> explode. "Why not word-level?" — huge vocab, no handling of unseen words or morphology.

## D2 · Scaled dot-product and multi-head attention

For queries $Q\in\mathbb R^{T_q\times d_k}$, keys $K\in\mathbb R^{T_k\times d_k}$, values $V\in\mathbb R^{T_k\times d_v}$:

```math
\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V
```

Each output is a convex combination of value vectors, weighted by query–key similarity — a soft, differentiable
dictionary lookup.

**Why $\sqrt{d_k}$?** If $q,k$ have i.i.d. unit-variance components, $q\cdot k$ has variance $d_k$. Without
scaling, logits grow with $d_k$, softmax saturates to one-hot, and gradients vanish.

**Masks** $M$ add $-\infty$ (in practice a large negative number, careful in FP16) to disallowed positions:
**causal** (position $t$ sees $\le t$) for autoregressive decoders; **padding** masks for batched variable
lengths; block/sliding-window masks for local attention. Convention bugs (True = keep vs True = mask) are common.

**Multi-head attention:** project into $h$ heads of size $d/h$, attend in parallel, concatenate, project out:

```math
\mathrm{MHA}(X)=\mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_h)W^O,\quad \mathrm{head}_i=\mathrm{Attn}(XW_i^Q,XW_i^K,XW_i^V)
```

Same FLOPs as one big head, but each head can attend to different things (syntax, position, coreference). In code:
one $d\times3d$ projection, reshape `(B,T,3,h,d_h)`, permute to `(B,h,T,d_h)`.

**Cost:** projections $O(Td^2)$; scores and weighted sum $O(T^2d)$; the $T\times T$ score matrix is
$O(T^2)$ memory per head (FlashAttention avoids materialising it — week 14). For short sequences the projections and
FFN dominate; for long sequences attention dominates.

**Self- vs cross-attention:** self-attention takes $Q,K,V$ from the same sequence; cross-attention takes $Q$ from the
decoder and $K,V$ from the encoder (translation, Whisper, conditioning in diffusion models).

In PyTorch, use `F.scaled_dot_product_attention(q, k, v, attn_mask=..., is_causal=True)`, which dispatches to
FlashAttention / memory-efficient kernels.

> **Interview angle.** You *will* be asked to implement MHA from scratch. Practise until you can write it, with a
> causal mask and a padding mask, in under 15 minutes and explain every reshape.

## D3 · The original block and the three families

**Original Transformer (2017):** encoder–decoder for translation. Each layer: attention → add & LayerNorm → FFN
(ReLU, $4d$ hidden) → add & LayerNorm (**post-norm**); sinusoidal positions; dropout; label smoothing; warmup +
inverse-sqrt LR.

**Families:**

| | Attention | Objective | Examples | Good for |
|---|---|---|---|---|
| Encoder-only | bidirectional | masked LM (15% tokens) | BERT, RoBERTa, DeBERTa, HuBERT | classification, retrieval embeddings |
| Decoder-only | causal | next-token prediction | GPT, Llama, Qwen, DeepSeek | generation, everything at scale |
| Encoder–decoder | bi + causal + cross | span corruption / seq2seq | T5, BART, Whisper | translation, ASR, summarisation |

**Why decoder-only won for LLMs:** one simple objective uses every token as a training signal; the same model does
any task via prompting; KV caching makes generation efficient; and it scales predictably. Encoders remain the right
choice for embedding/retrieval models and many speech tasks; encoder–decoders for ASR/translation with strong
input conditioning.

**Vision Transformer (ViT):** patch embedding + learned positions + a `[CLS]` token (or mean pooling), standard
encoder. **Conformer** for speech (week 8). **DiT** for diffusion (week 16).

**Parameter count per layer** (ignoring norms/biases): attention $4d^2$ + FFN $8d^2$ (for $4d$ hidden) $=12d^2$;
total $\approx12Ld^2 + Vd$. GPT-3 175B: $L=96$, $d=12288$ → $12\cdot96\cdot12288^2\approx174$B. ✓

> **Interview angle.** "BERT vs GPT?" — bidirectional context with MLM (great representations, can't generate
> left-to-right naturally) vs causal LM (generates, every token is supervised).

## D4 · Positional encodings I: absolute and relative bias methods

Self-attention is **permutation-equivariant**: shuffle the input tokens and the outputs shuffle the same way.
Without positional information "dog bites man" = "man bites dog". (A causal mask leaks some position info — "NoPE"
models can work — but explicit encodings are standard.)

**Sinusoidal absolute** (original): add to the embedding

```math
PE_{(t,2i)}=\sin\!\big(t/10000^{2i/d}\big),\qquad PE_{(t,2i+1)}=\cos\!\big(t/10000^{2i/d}\big)
```

Geometric progression of wavelengths; $PE_{t+k}$ is a linear function (rotation) of $PE_t$, which in principle
lets the model attend by relative offset. No parameters; extrapolates poorly in practice.

**Learned absolute** (BERT, GPT-2): a trainable table of max-length size; can't go beyond it.

**Relative position methods** make attention depend on $i-j$ directly:

* **Shaw et al.:** learned relative embeddings added to keys/values for clipped offsets.
* **T5 relative bias:** a learned scalar bias per head per **log-spaced bucket** of offset, added to the logits.
* **ALiBi:** no learned params; add $-m_h\,|i-j|$ to the logits with a fixed slope per head (geometric
  sequence). A linear distance penalty → strong recency bias and good length extrapolation; used by BLOOM, MPT.

**Where it's added matters:** absolute methods add to the input embeddings (position mixes with content in every
layer); bias methods act on attention logits only (content and position kept separate); RoPE (tomorrow) rotates
$q$ and $k$.

> **Interview angle.** "Why can't learned absolute positions extrapolate?" — positions beyond the table were never
> trained, and there's nothing in the representation that relates position 5,000 to 4,000.

## D5 · Positional encodings II: RoPE, partial RoPE and context extension

**Rotary Position Embedding (RoPE)** (Su et al., used by almost every modern LLM). Split each query/key into 2-D
pairs and rotate pair $i$ at position $m$ by angle $m\theta_i$, with $\theta_i = b^{-2i/d}$ (base $b$ = 10,000
originally; Llama 3: 500,000; Qwen: 1,000,000+). In complex form, $\tilde q_m = q\,e^{im\theta}$, so:

```math
\mathrm{Re}\big[\tilde q_m\,\overline{\tilde k_n}\big]=\mathrm{Re}\big[q\,\bar k\,e^{i(m-n)\theta}\big]
```

The score depends only on the **relative** offset $m-n$, while positions are injected multiplicatively, with no
extra parameters, and it's compatible with KV caching (keys are rotated once when written). Low-frequency pairs
(large $i$) rotate slowly and carry long-range/semantic information; high-frequency pairs encode local order.

**Implementation detail that breaks checkpoints:** "interleaved" pairs (x0,x1),(x2,x3)… vs "half-split" pairs
(x_i, x_{i+d/2}) (`rotate_half` in Llama/HF). Mathematically equivalent up to a permutation of dimensions, but
weights trained one way need the matching code.

**Partial RoPE:** rotate only a fraction of the head dimension and leave the rest position-free (GPT-NeoX 25%;
Qwen3.5's gated attention layers use `partial_rotary_factor = 0.25`). **DeepSeek MLA** uses *decoupled* RoPE: a small
separate rotary part of the key shared across heads, because RoPE would break MLA's matrix absorption (week 18).
**NoPE** layers (no positional encoding) are mixed with RoPE layers in some long-context designs; linear-attention /
DeltaNet layers in hybrids often need no RoPE because their recurrence is order-aware.

**Context extension** (train at 4–32K, run at 128K–1M):

* **Position interpolation (PI):** scale positions $m\to m\cdot L_{train}/L_{target}$ — squeezes everything,
  hurts local resolution; needs some fine-tuning.
* **NTK-aware scaling:** increase the base $b$ so high frequencies are almost unchanged and low frequencies are
  interpolated.
* **YaRN:** per-frequency interpolation ("NTK-by-parts": don't touch high frequencies, interpolate low ones, blend
  in between) + an attention temperature correction. Used by Qwen (262K native → ~1M with YaRN for Qwen3.5) and
  DeepSeek for context extension.
* **Progressive training** on longer sequences with a raised base is the most reliable approach.

> **Interview angle.** Derive the relative property in two lines with complex numbers, then say *why* it matters:
> relative-position awareness, no learned table, KV-cache friendly, and a principled knob (the base) for
> extending context.

## Questions

??* d1 [tokenisation] | How does BPE tokenisation work, and what are the trade-offs of vocabulary size?
Training: start from a base vocabulary (bytes or characters), count adjacent symbol pairs in the corpus, merge the
most frequent pair into a new token, repeat until the target vocabulary size; encoding applies the learned merges
in order. Bigger vocabularies shorten sequences (cheaper attention, more content per context, better multilingual
coverage) but enlarge the embedding table and output softmax and leave rare tokens under-trained; smaller vocabularies
lengthen sequences. Byte-level BPE guarantees every string can be encoded.

?? d1 [embeddings] | What is weight tying and when is it used?
Using the same matrix for the input embedding and the output (LM head) projection, transposed. It saves V·d
parameters (large when V is big relative to the model) and acts as a regulariser. Small and on-device models usually
tie (e.g. small Gemma/Qwen sizes); many large models untie because the extra parameters are cheap relative to total
size and untied heads perform slightly better.

??* d2 [attention] | Why divide by √d_k in scaled dot-product attention?
With independent zero-mean, unit-variance components, q·k = Σ qᵢkᵢ has variance d_k, so its standard deviation grows
as √d_k. Large logits push softmax into saturation (near one-hot), where gradients are tiny and training is unstable.
Dividing by √d_k keeps logits at unit variance regardless of head size. QK-norm and logit soft-capping are later
fixes for logits that still grow during training.

??* d2 [attention] | What are the compute and memory costs of self-attention, and which part dominates when?
Q/K/V/O projections cost O(T·d²); scores QKᵀ and the weighted sum cost O(T²·d); the score matrix takes O(h·T²) memory
if materialised. With the FFN (O(T·d²), ~2/3 of layer FLOPs at short context), short sequences are dominated by the
d² terms; attention dominates once T is comparable to or larger than ~d (e.g. T > 4–8K for d = 4096). FlashAttention
removes the T² memory but not the T² compute.

?? d2 [attention] | What's the purpose of multiple heads?
Each head has its own projections and can attend to different positions/relations (local syntax, long-range
references, positional patterns) at the same total cost as one wide head, since each head has dimension d/h. It also
gives a natural unit for parallelism and for KV-sharing schemes (MQA/GQA). Many heads turn out to be redundant and
can be pruned, which is part of why sharing K/V across heads works.

??* d3 [architecture] | Encoder-only vs decoder-only vs encoder–decoder — when would you use each?
Encoder-only (BERT, HuBERT): bidirectional context, trained with masked prediction; best for classification, tagging,
retrieval embeddings and representation learning. Decoder-only (GPT, Llama, Qwen, DeepSeek): causal, next-token
training on every token; generation and general-purpose LLMs, efficient KV-cached decoding. Encoder–decoder (T5,
Whisper): bidirectional encoding of a full input plus autoregressive generation with cross-attention; strong for
input-conditioned tasks such as ASR and translation. Decoder-only dominates at scale for its simplicity and scaling.

?? d3 [architecture] | Estimate the parameter count of a transformer from L, d and V.
Per layer: attention Q, K, V, O = 4d²; FFN with hidden 4d = 8d² (SwiGLU with hidden 8d/3 also ≈ 8d²); total ≈ 12d² per
layer. Model ≈ 12·L·d² + V·d (embeddings, ×2 if untied head). With GQA, K/V shrink to 2·d·d_kv. Example: L = 32,
d = 4096 → 12·32·4096² ≈ 6.4B, plus 128K × 4096 ≈ 0.5B per embedding matrix → ~7–8B.

??* d4 [positional] | Why do transformers need positional encodings, and what's the difference between absolute and relative schemes?
Self-attention is permutation-equivariant: without position information the model can't tell word order. Absolute
schemes (sinusoidal, learned) add a vector for each position to the input embedding; learned tables can't exceed their
trained length and both extrapolate poorly. Relative schemes make attention depend on the offset i − j (Shaw, T5 bias
buckets, ALiBi, and RoPE), which matches the translation-invariant nature of language and usually extrapolates better.

?? d4 [positional] | How does ALiBi work and why does it extrapolate?
It adds a fixed linear penalty −m_h·|i − j| to the attention logits, with a different slope m_h per head (a geometric
sequence), and no positional embeddings at all. Distant tokens are softly down-weighted, giving a recency bias that
behaves the same at any length, so models trained on short contexts degrade gracefully on longer ones. The cost is
that strong recency bias can limit very long-range retrieval.

??* d5 [positional, rope] | Explain RoPE and prove it encodes relative position.
Group each query/key vector into 2-D pairs and rotate pair i by angle m·θᵢ at position m, θᵢ = b^(−2i/d). Treat a pair as
a complex number: q̃ = q·e^{imθ}, k̃ = k·e^{inθ}. The real part of q̃·conj(k̃) = Re[q·conj(k)·e^{i(m−n)θ}], which depends only on
m − n. So attention scores are functions of content and relative offset, without a learned table; keys are rotated
once when cached; and the base b controls the wavelength range, which is the knob for extending context (NTK/YaRN).

??* d5 [positional, long-context] | How do PI, NTK-aware scaling and YaRN extend a RoPE model's context?
Position Interpolation divides positions by the extension factor so all positions fall in the trained range; it
compresses high-frequency (local) information and needs fine-tuning. NTK-aware scaling raises the RoPE base, so
high-frequency dimensions barely change and low-frequency ones are effectively interpolated. YaRN applies different
treatment per frequency band — leave high frequencies alone, interpolate low ones, blend in between — and adds an
attention temperature correction; it extends context with little fine-tuning and is used by Qwen and DeepSeek.

?? d5 [positional] | What is partial RoPE and why might a model rotate only part of each head?
Only a fraction (e.g. 25%) of each head's dimensions get rotary encoding; the rest carry position-independent content.
This keeps some dimensions free for purely semantic matching, can improve length generalisation, and saves compute.
GPT-NeoX used it; Qwen3.5's gated attention layers rotate 25% of the head dimension. DeepSeek's MLA uses a related idea:
a small decoupled RoPE key component, because applying RoPE to the compressed latent would prevent absorbing the
up-projection into the query.
