## D1 · Where attention costs come from, and local attention

Two phases with different bottlenecks:

* **Prefill** (processing the prompt): $O(T^2d)$ compute, highly parallel → compute-bound.
* **Decode** (one token at a time): each new token reads the **whole KV cache** ($O(T)$ memory traffic per token) →
  bandwidth-bound; total $O(T^2)$ over a generation.

**Sliding-window attention (SWA):** each token attends to the last $w$ tokens only (Mistral 7B: $w=4096$). Compute
$O(Tw)$, KV cache capped at $w$. Information still propagates further through depth (receptive field ≈ $L\cdot w$).
Modern models **interleave** local and global layers: Gemma 3 uses 5 local (1K window) : 1 global; gpt-oss
alternates dense and banded; this cuts KV memory by ~5× with little quality loss.

**Attention sinks / StreamingLLM:** with a rolling window, evicting the first tokens breaks the model (they hold
attention mass). Keep a few initial "sink" tokens + a recent window → stable infinite-length streaming generation (but
no recall of evicted middle content).

**Chunked/blocked attention:** process long prompts in chunks to bound memory (chunked prefill); block-diagonal
attention for packed sequences (document masking so packed samples don't attend to each other).

> **Interview angle.** "How would you let an on-device assistant keep a conversation going forever with fixed
> memory?" → sink tokens + sliding window (or a recurrent/linear-attention layer), plus summarisation into a short
> memory.

## D2 · Linear attention and Lightning Attention

Replace $\exp(q^\top k)$ with a kernel feature map $\phi(q)^\top\phi(k)$. Then associativity lets us reorder:

```math
o_t=\frac{\sum_{s\le t}\phi(q_t)^\top\phi(k_s)\,v_s}{\sum_{s\le t}\phi(q_t)^\top\phi(k_s)}=\frac{\phi(q_t)^\top S_t}{\phi(q_t)^\top z_t},\qquad S_t=S_{t-1}+\phi(k_t)v_t^\top
```

The causal form is an **RNN** with a matrix-valued state $S_t\in\mathbb R^{d_k\times d_v}$: $O(1)$ memory and compute
per decoded token, $O(T)$ total. Training uses a **chunkwise parallel** form (full attention within a chunk, recurrent
state passed between chunks) to use matmuls efficiently.

**Weaknesses:** the state has fixed capacity ($d_k\times d_v$); plain linear attention only *adds* to it, so old
associations are never removed and retrieval of specific tokens ("what was the phone number?") is poor. Fixes add
**decay** (RetNet, RWKV, GLA, Mamba-2: $S_t=\gamma_tS_{t-1}+k_tv_t^\top$) and the **delta rule** (tomorrow).

**Lightning Attention (MiniMax):** an IO-aware linear-attention kernel — conventional attention inside blocks, the
linear (kernel-trick) form between blocks — avoiding the slow cumulative-sum of naive causal linear attention.
**MiniMax-01 / M1** used a hybrid of 7 lightning layers : 1 softmax layer, giving 1M-token context and, for M1, ~25% of
DeepSeek-R1's FLOPs at 100K generation length. **MiniMax M2** then returned to full attention (week 11 D5) — efficient
attention looked equal on benchmarks but lagged on complex multi-hop/agentic tasks.

> **Interview angle.** Show that causal linear attention's parallel and recurrent forms are identical (you'll
> implement both), and explain why the recurrent form is great for streaming inference on a DSP.

## D3 · State-space models and the delta rule: Mamba, Gated DeltaNet, KDA

**State-space models:** $h_t=\bar Ah_{t-1}+\bar Bx_t$, $y_t=Ch_t$ (discretised continuous system — familiar from your
SSP/Kalman work!). S4 used structured $A$ and FFT-based convolution for training. **Mamba** made $\Delta,B,C$
**input-dependent** ("selective"), so the model decides what to remember or forget, with a hardware-aware parallel scan.
**Mamba-2** showed SSMs with scalar decay are a form of linear attention ("state-space duality") and trained them with
matmuls.

**DeltaNet** updates the associative memory with the **delta rule** — it first reads what the memory currently returns
for key $k_t$ and writes only the correction:

```math
S_t=S_{t-1}+\beta_t\,(v_t-S_{t-1}k_t)\,k_t^\top=S_{t-1}\big(I-\beta_tk_tk_t^\top\big)+\beta_tv_tk_t^\top
```

(with $S$ mapping keys to values, $o_t=S_tq_t$, keys L2-normalised). This is online gradient descent on
$\|Sk_t-v_t\|^2$ — exactly the **LMS/NLMS adaptive filter update** you know from echo cancellation, with $\beta_t$
as a learned, data-dependent step size. It can overwrite stale associations, so recall is much better than additive
linear attention.

**Gated DeltaNet** (Yang et al.) adds a decay gate $\alpha_t\in(0,1)$: $S_t=\alpha_tS_{t-1}(I-\beta_tk_tk_t^\top)+\beta_t
v_tk_t^\top$ — fast forgetting + precise updates. **Qwen3-Next and Qwen3.5** use **3 Gated DeltaNet layers : 1 gated
full-attention layer** (Qwen3.5-397B: 45 DeltaNet + 15 attention layers), giving ~30 KB KV cache per token and
262K native context.

**Kimi Delta Attention (KDA)** refines Gated DeltaNet with **channel-wise** (per-dimension) gating instead of a scalar
gate, plus an efficient chunkwise kernel. **Kimi Linear** (48B-A3B) uses 3 KDA : 1 MLA and reported beating full
attention at equal training with up to ~6× faster decoding at 1M context; **Kimi K3** uses 69 KDA + 24 gated-MLA layers.

**Why hybrids?** Linear/recurrent layers carry most of the sequence mixing cheaply; a few full-attention layers keep
exact retrieval. Full-attention layers in these hybrids can even drop RoPE, since the recurrent layers are order-aware.

> **Interview angle.** Connect the delta rule to NLMS explicitly — it's a memorable, correct insight that shows your
> signal-processing background is an asset for modern LLM architectures.

## D4 · Learned sparse attention: NSA, MoBA, DSA and DeepSeek-V4's CSA/HCA

Sparse attention keeps softmax attention but lets each query look at only a subset of keys.

* **Fixed patterns:** Longformer/BigBird (local window + global tokens + random links). Simple but content-blind.
* **NSA — Native Sparse Attention (DeepSeek, 2025):** three branches combined with learned gates — **compressed**
  (attend to block summaries), **selected** (pick top blocks by compressed scores, attend to their full tokens),
  **sliding window** (recent tokens) — designed for hardware-aligned block access and trained end to end.
* **MoBA (Moonshot):** "Mixture of Block Attention": route each query to the top-k key blocks, like MoE routing over
  blocks.
* **DSA — DeepSeek Sparse Attention (V3.2):** a tiny **lightning indexer** (few heads, FP8, ReLU-scored dot products)
  computes a relevance score between the query and every previous token; only the **top-k tokens** (e.g. 2,048) are
  attended by the main MLA attention. Main attention becomes $O(Tk)$; the indexer is still $O(T^2)$ but extremely
  cheap. Trained by first distilling the indexer from dense attention, then sparse training. **GLM-5** adopted MLA + DSA;
  GLM-5.2 adds **IndexShare** (some layers reuse the previous layer's top-k selection).
* **DeepSeek-V4 hybrid attention:** alternates **CSA** — Compressed Sparse Attention: KV compressed 4× along the sequence
  with learned (softmax-gated) pooling, then an FP4 lightning indexer selects top-k compressed blocks, plus a
  sliding-window branch of uncompressed recent tokens — and **HCA** — Heavily Compressed Attention: KV compressed 128×,
  attended densely (cheap because the compressed sequence is short), again with a sliding window. Most KV stored in FP8.
  Reported at 1M context: V4-Pro needs ~27% of V3.2's per-token FLOPs and ~10% of its KV cache (V4-Flash: 10% and 7%).

**Sparse vs linear:** sparse attention keeps exact access to selected tokens (good retrieval) but the cache still grows
with $T$ (compression helps); linear/recurrent layers have constant state but lossy memory. 2026 frontier models mix
both ideas.

> **Interview angle.** "What does DSA's indexer cost?" — still quadratic in principle, but with a few low-dimensional
> FP8 heads it's a small fraction of full attention; the expensive main attention becomes linear in $T$ for fixed $k$.

## D5 · Long-context training, evaluation and KV compression

**Training for long context:** pre-train at 4–8K, then extend in stages (32K → 128K → 1M) with a raised RoPE base or YaRN
on long-document-enriched data; DeepSeek-V4's 32T-token pre-training includes staged extension to 1M. Packing with
document masks; sequence/context parallelism to fit activations (week 15).

**Evaluation:** needle-in-a-haystack is too easy (single exact retrieval). **RULER** adds multi-needle, multi-hop tracing,
aggregation; LongBench, ∞Bench, MRCR, and agentic long-horizon tasks. "Lost in the middle": models use the beginning and
end of the context better than the middle. **Effective context** is often far shorter than advertised.

**KV cache compression at inference** (training-free): evict low-attention tokens (H2O, SnapKV, scissorhands), keep
sinks + recent; quantise KV to FP8/INT4 (per-channel for keys, per-token for values — keys have outlier channels);
merge similar tokens; offload to CPU/SSD (Mooncake-style KV stores).

**Long context vs RAG:** retrieval keeps prompts short and cheap and cites sources; long context avoids retrieval errors
and lets the model reason across a whole document. On-device, retrieval over a local index plus a short context is usually
the efficient choice.

> **Interview angle.** "Your model claims 128K context but fails at 40K" → check RoPE scaling config at inference,
> evaluate with RULER-style tasks, look for position-dependent failure, and check KV quantisation/eviction settings.

## Questions

??* d1 [attention, inference] | Why is LLM decoding memory-bound while prefill is compute-bound?
Prefill processes all prompt tokens in parallel: each weight loaded from memory is reused across many tokens (large
matmuls), so arithmetic intensity is high and compute is the limit. Decode generates one token per sequence per step:
each weight and the entire KV cache are read to do roughly one multiply-add per weight per sequence, so arithmetic
intensity ≈ batch size; at small batch the hardware waits on memory. Batching, quantisation, KV compression and
speculative decoding all raise useful work per byte read.

?? d1 [attention] | How does sliding-window attention still model long-range dependencies?
Each layer attends to a window of w tokens, but stacking L layers lets information flow up to ≈ L·w tokens through
intermediate positions, like stacked convolutions. In practice models interleave a few global layers (Gemma 3's 5:1
local:global) for exact long-range access while most layers stay cheap.

??* d2 [linear-attention] | Show that causal linear attention can be computed as an RNN.
With kernelised scores φ(q_t)ᵀφ(k_s), o_t = Σ_{s≤t} φ(q_t)ᵀφ(k_s) v_s / Σ_{s≤t} φ(q_t)ᵀφ(k_s). Pull φ(q_t) out of the sums:
o_t = φ(q_t)ᵀS_t / φ(q_t)ᵀz_t with S_t = S_{t−1} + φ(k_t)v_tᵀ and z_t = z_{t−1} + φ(k_t). So each step updates a d_k×d_v
state in O(d_k·d_v) — constant in t — instead of attending over all past tokens. Training uses a chunkwise parallel form.

?? d2 [linear-attention] | What are the main weaknesses of linear attention compared with softmax attention?
The fixed-size state has limited capacity and purely additive updates never erase old associations, so precise recall
of specific earlier tokens and in-context retrieval degrade, especially over long contexts. The kernel feature maps
approximate softmax's sharp, normalised weighting poorly. Decay gates, the delta rule, larger states and hybrid stacks
with a few full-attention layers address this.

??* d3 [ssm, delta-rule] | What is the delta rule in DeltaNet, and how does it relate to adaptive filtering?
DeltaNet treats the state S as an associative memory mapping keys to values. Instead of adding v_t k_tᵀ, it first reads the
current prediction S_{t−1}k_t and writes only the error: S_t = S_{t−1} + β_t(v_t − S_{t−1}k_t)k_tᵀ. That is one step of
online gradient descent on ||S k_t − v_t||², i.e. the LMS/NLMS update with a learned step size β_t (and normalised keys),
so it can overwrite stale associations. Gated DeltaNet adds a decay α_t; Kimi's KDA makes the decay channel-wise.

??* d3 [ssm, chinese-models] | Describe Qwen3.5's hybrid attention architecture and why it's designed that way.
Layers follow a repeating pattern of three Gated DeltaNet (linear-attention, delta-rule) layers followed by one gated
full-attention layer (with GQA and partial RoPE), each followed by a sparse MoE FFN. The DeltaNet layers give
constant-size state and linear-time sequence mixing; the 1-in-4 softmax layers preserve precise retrieval; output gating
removes attention sinks and massive activations. The result is a much smaller KV cache and faster long-context decoding
with quality comparable to full attention.

?? d3 [ssm] | What makes Mamba "selective", and why does that matter?
Classic SSMs like S4 use fixed (input-independent) A, B, C, so they're linear time-invariant systems — efficient via
convolution but unable to decide what to store based on content. Mamba makes the step size Δ and the B and C matrices
functions of the input, so the model can choose per token to retain or ignore information (like gates in an LSTM). That
breaks the convolution view, so Mamba uses a hardware-aware parallel scan; Mamba-2 restricts A to scalar decay to train
with matmuls (linear-attention duality).

??* d4 [sparse-attention, chinese-models] | How does DeepSeek Sparse Attention (DSA) work?
A lightweight lightning indexer — a few small heads, run in FP8 with ReLU activations — computes an index score between the
current query token and every previous token. The top-k (e.g. 2,048) tokens by score are selected, and the main MLA
attention is computed only over them. The main attention's cost becomes O(T·k) instead of O(T²); the indexer is still
quadratic but tiny. It was trained by first aligning the indexer with dense attention scores, then continuing training with
sparse selection. GLM-5 adopted it.

??* d4 [sparse-attention, chinese-models] | What are CSA and HCA in DeepSeek-V4?
Two attention types alternated across layers. CSA (Compressed Sparse Attention) pools KV entries 4× along the sequence with
learned softmax-gated pooling, uses an FP4 lightning indexer to pick the top-k compressed blocks for each query, and adds a
sliding-window branch of recent uncompressed tokens. HCA (Heavily Compressed Attention) compresses KV 128× and attends to all
compressed blocks densely (cheap because the sequence is short), also with a sliding window. Together with FP8 KV storage
they cut per-token FLOPs to ~27% and KV cache to ~10% of DeepSeek-V3.2 at 1M context for V4-Pro.

?? d5 [long-context] | Why is needle-in-a-haystack insufficient for evaluating long-context models?
It tests a single exact-match retrieval of an out-of-place sentence, which even weak long-context mechanisms can solve via
lexical matching. Real use requires multiple retrievals, multi-hop reasoning, aggregation across the whole context, tracking
state, and resisting distractors. RULER, LongBench, MRCR and long-horizon agent tasks test these and reveal that effective
context is often much shorter than the advertised window.

?? d5 [kv-cache] | How would you compress the KV cache of a deployed model without retraining?
Quantise KV to FP8 or INT4 (keys per-channel because of outlier channels, values per-token, with small groups); evict tokens
with low accumulated attention while keeping attention-sink and recent tokens (H2O/SnapKV/StreamingLLM); share or merge
similar tokens; limit context with sliding windows where the model tolerates it; offload cold KV to CPU/SSD. Validate on
long-context tasks, since eviction can silently break retrieval.
